      Where the numbers on this page come from
      
Measured on 2026-09-02 on one developer machine. Cost is the robust number here,
        not speed — 7.8× cheaper per judgement reproduces; the latency win is a noisy
        2.5–3.5× on the median with a tail that sometimes loses the race outright. Latencies are
        wall-clock and vary with your host, your network and your model choice; they are not a
        service level.

      

        
          

            Deterministic tier
            The PermissionRequest hook round trip that resolves a call by rule
              alone, with no model involved: 3–4 ms end to end. The classifying
              function itself, in process, is 0.0005 ms. Most read-only calls end
              here. This is the number the demo shows.
          

          

            Cost per judgement
            Uncached → cached: claude-opus-5
              $0.042799 → $0.005463 (7.8× cheaper) ·
              claude-sonnet-5 $0.017234 → $0.002302 ·
              claude-haiku-4-5 $0.006122 → $0.000261 (23×).
          

          

            Model tier
            When a call needs judgment, a direct API call with a warm prompt cache:
              5,559 ms median for claude-opus-5 (n=12, min 3,977 ms,
              max 15,180 ms) · 3,117 ms median for claude-haiku-4-5
              (n=5, min 2,825 ms, max 13,385 ms). The
              median is not a guarantee: the tail is real, and roughly 1 in 12
              samples exceeded the tier's 10 s timeout and fell through to the subprocess below,
              paying its full cost. claude-sonnet-5 measured 10,033 ms median — above
              that timeout, so it is the wrong choice here despite being cheaper.
          

          

            What that replaced
            Shelling out to a claude -p subprocess per judgement:
              ~13.5 s (range 11.2–16.7 s, n=3), of which fixed boot, auth and
              round trip alone was ~7.5 s median (n=6). So the honest speedup is
              roughly 2.5–3.5× on the median — not an order of magnitude. Process
              boot was never the whole cost.
          

          

            Prompt cache
            After the first judgement, 11,286 tokens of the prefix are read
              from cache against ~770 newly written — a
              98.9% cache hit. This only applies to sessions long enough to cache:
              the minimum cacheable prefix is model-dependent (~2,048 tokens on Haiku) and a shorter
              one silently caches nothing at all, with no error.
          

          

            2,898 tests · zero dependencies
            2898 passed (2898) across 117 files from make check on
              2026-09-07. package.json declares no dependencies field at
              all, so nothing ships alongside the extension. TypeScript-only is enforced in CI by
              ci/check-no-python.sh and ci/check-naming.sh.
          

        
      

    

  







  

    
Silence is never approval.

      writes an approval. A red one that nobody answers stays blocked. That is the whole rule, and
      every other behaviour on this page follows from it.

Isn't this already in Claude Code?

    
Partly, and it is worth being exact about which parts — the answer
      is the reason this project still has a shape.


    

      

        
First-party today

        
Agent view (claude agents) is a first-party worklist of
          Claude Code sessions — grouped by Needs input / Working /
          Completed, with waiting timers, peek and attach. It is good, and if you only run
          Claude Code on one machine it is probably all the worklist you need. Its sessions are
          local to that machine and to that one agent.

      

      

        
What is left over

        
Four agents wide — Claude Code, IBM Bob IDE, Codex CLI, VS Code Chat — unioned across
          every window you have open and across peer machines reached over SSH, with one click
          focusing the window that owns the session even when that window is on the other box.

      

    


    

      

        
First-party today

        
Auto mode is a first-party classifier that reviews every tool call and
          blocks the irreversible ones. It is on by default on Pro, Max and Team plans, it reads
          your CLAUDE.md, and you should leave it on: it is a strictly
          better default than approving everything by reflex. What it does not do is tell you
          which of your rules it applied — a blocked call reports
          Blocked by classifier — and it keeps no record you can hand to anyone
          afterwards.

      

      

        
What is left over

        
Your clause, by name. The rewrite, so a blocked agent is handed the safe call and the run
          continues. The explicit deny-on-timeout for the genuine judgment calls. One durable record
          per decision. Both layers can be on at once, and the supervision half of the extension is
          off until you turn it on.

One engine, three front ends

    
One supervision engine decides, records and notifies. The front
      ends only carry the prompt to it — so a rule you write once holds in the panel, in a bare
      terminal session, and in a replay. All three ship today.

Onboarding, in three steps

    
Install a front end, then hand the configuring to an agent.
      There are 42 settings and you should not have to read about any of them — a skill in this
      repository interviews you, writes the file, and then a script says whether it worked.


    
    

      
  1. 
        
    Install a front end
    
        
    Both drive the same supervision engine, and neither needs the other.
          Take the plugin if you work in the terminal, the extension if you want the panel — or
          both, on the same machine.
    

        
    
          
    
            
    
              
    Claude Code plugin
    
              no download
            
    
            
    

    /plugin marketplace add eranra/session-sitter
/plugin install session-sitter@session-sitter
    
              
            
    
            
    Two slash commands, typed inside Claude Code. Nothing to download,
              no window to reload. It brings the hooks that answer every permission prompt and
              seven /session-sitter:* commands —
              PLUGIN.md
              covers all of them.
    
          
    

          
    
            
    
              
    VS Code extension
    
              by VSIX
            
    
            
    

    code --install-extension session-sitter-*.vsix
    
              
            
    
            
    Not on the Marketplace yet, so take the .vsix from the
              latest release
              — or the IDE route, Extensions panel → ··· →
              Install from VSIX… Every pull request attaches a build under its CI
              run's Artifacts, so you can install the exact code under review.
    

            
    
              Or build it from source
              
    

    git clone https://github.com/eranra/session-sitter.git
cd session-sitter
make install
    
                
              
    
              
    Then reload the window — Ctrl+Shift+P →
                Developer: Reload Window. For another VS Code build, point
                make install at its CLI: make install CODE=bobide for IBM
                Bob IDE, or CODE=cursor, CODE=code-insiders.
    
            
    
          
    
        
    
      
    2. 

      
  2. 
        
    Let an agent do the configuring
    
        
    docs/onboarding/
          is an Agent Skill — instructions any agent that reads skills will follow to set this up
          for you. It asks what you want, proposes the settings in words before writing them, and
          validates the result with a script rather than from memory. Paste this at Claude Code,
          IBM Bob, or whatever you run:
    

        
    

    Read docs/onboarding/SKILL.md and set up Session Sitter for me.
    
          
        
    

        
    
          
    
            
    Have it in every session
    
            
    

    mkdir -p ~/.claude/skills/configuring-session-sitter
cp -r docs/onboarding/* ~/.claude/skills/configuring-session-sitter/
    
              
            
    
            
    Then just say what you want — "turn on Telegram cards",
              "why isn't my auto-approve rule firing?", "review my Session Sitter
              configuration". The skill answers to all three.
    
          
    
          
    
            
    Or read it yourself
    
            
    Nothing here needs an agent. SKILL.md
              is written in the order a configuration is actually built, so it reads as a
              getting-started guide — with seven complete
              example configurations
              to copy, one per layer, each of them re-validated by CI so a typo in one cannot
              reach you.
    
          
    
        
    
      
    3. 

      
  3. 
        
    Prove it took
    
        
    This step exists because of one failure mode: VS Code ignores
          a setting id it does not recognise. No error, no warning — just a feature that
          never turns on. So the skill does not trust a list of settings, and neither should you.
    

        
    

    node docs/onboarding/scripts/ss-config.mjs where     # which settings.json is the live one
node docs/onboarding/scripts/ss-config.mjs check     # what is on, and what is broken
    
          
        
    

        
    The doctor reads the declared settings out of the build in front of you,
          so a renamed or removed one shows up the moment the extension changes.
          where answers the question behind most "I changed it and nothing happened"
          reports — several settings.json files usually exist and only one is read.
          check resolves settings, the environment and your .env in the
          same precedence order the extension uses, so it can say whether a feature is actually
          on, which a settings file alone cannot. No dependencies, no network, and it
          never writes a file.

What you need

        

          
VS Code or IBM Bob IDE
1.65 or later — for the extension. The plugin needs only Claude Code.

          
Linux, WSL or macOS
for Claude liveness detection — /proc/<pid>/stat on Linux, ps elsewhere

          
python3
to read IBM Bob's SQLite store. Only needed for Bob sessions.

          
Node 20+
for the doctor in step 3, and to build from source

        

        
Zero runtime dependencies — package.json declares no
          dependencies at all. Nothing is installed alongside it.

      

      

        ◆
        
Stopping early cannot auto-approve anything. With no supervisor
          and no rules configured, Session Sitter watches and reports and decides nothing — and two
          guards hold whatever you configure later: a question meant for you is never auto-approved,
          and neither is a request whose metadata the hook did not see. Silence is never
          approval.
